# 第二检测点停靠复用实验

本轮只运行离线模拟器，没有连接本机2026端口。所有方案保持七点连续1000米覆盖和清除闭环。

## 实现与筛选

- 新增默认关闭的 `planned_stop_reuse`。
- 最终保留的实现只在机器狗已经真实到达某个停靠点后检查复用，避免把会随新观测变化的未来清除质心误当成必访点。
- 复用点必须通过问题2候选区域的充分条件：对边界修正后的一次观测扇形，最坏接收距离不超过1000米、交会角不小于31度；角度检查包含0.005001度显示舍入容差。
- 满足条件才原地补测；不满足时完全沿用动态点/固定点混合策略。

## 30局同种子初筛（50000—50029，413个源）

| 实验目录/方案 | 平均时间/s | 平均请求 | 结论 |
|---|---:|---:|---|

| `pilot30_actual_stop/dynamic_reuse`，仅已到达点严格复用 | 3313.936 | 170.37 | 与动态R混合逐局完全相同；30局没有严格复用机会 |

| `pilot30_defer_scan/dynamic_reuse`，软延期到未来扫描点 | 3337.463 | 168.10 | 少2.27请求但多23.527秒，路线变差，删除 |
| `pilot30_defer_next_only/dynamic_reuse`，只准下一动作延期 | 3363.094 | 169.80 | 比动态R混合慢49.158秒，删除 |

另在 `../dynamic_R_gate_20260912/pilot30/` 测试动态点绕路节省门槛：50米门槛3317.269秒，
100米以上与原固定策略完全相同，均不优于无门槛动态R的3313.936秒，因此门槛参数未保留。

每个子目录都保存 `manifest.json`、源码哈希与快照、有效配置、逐局 `cases.jsonl` 和完整事件/真值。

## 结论

“已有点落入严格候选区域就复用”在数学上安全，但机会极少；软延期虽然减少检测请求，却会破坏移动路线，
而移动时间是主要成本。最终只保留零路线扰动的严格复用实验开关，不替换
`configs/optimized_threefix.json`，也不建议直接用于真实演练。

## 最终决策摘要

1. 边界动态 `R` 能显著缩短孤立的 `S1→P2`，但200局完整任务中强制动态点平均慢6.232秒，
   动态/固定混合平均慢3.295秒，因此不进入主配置。
2. 已有停靠点若严格位于候选区域，复用必然安全；但30局没有出现一次严格机会。把条件放宽为软延期后
   平均慢23.527—49.158秒，因此软延期代码撤回。
3. 两个想法都不是数学错误；它们没有提速的共同原因是优化了局部第二检测，却没有降低整条
   “扫描—验证—清除”路线的总移动距离。
4. 后续若继续提速，应优先研究全局移动路线和扫描/清除任务联合决策，不再围绕第二检测点添加权重或门槛。
