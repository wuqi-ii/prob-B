# 搜索与联合行程实验（2026-09-12）

## 结论

保持原默认 `route_insert` 不变，新方案仅通过配置开关启用。动态覆盖有小幅收益；联合行程没有收益，两者组合也没有统计上明确的优势。本轮不能支持“大幅提速”的结论。

## 实现边界

- 第一项：逐频道记录实际无信号检测；用1000米圆域并集覆盖整个1800米目标圆域作为排查依据。
- 用四叉树证明连续区域覆盖：整个方格都在某个接收圆内才排除；未决方格继续细分，达到深度上限仍未证明就返回“未获证明”。不使用稀疏采样点当作覆盖证明。
- 重新规划剩余扫描位置：候选包括原计划，以及1150/1350/1550米环半径、0/30度旋转的布局。所有检测覆盖半径仍为1000米；允许移动扫描中心不等于放宽接收半径。
- 在服务停靠点，仅当预计后续行走/检测节省超过新增检测成本时，执行未知频道检测。
- 计划中的检测位置只能用于规划，不能作为已经排除区域的证据；停止判据只读取实际历史。
- 题设最多16个源：实际已发现16个频道后，可以免做其他空频道排查，但仍必须成功清除所有已知源。
- 第二项：用首次示向可行域（含1500米最大接收距离）的质心估计目标位置，联合考虑“到验证点→到预计目标→接回后续路线”。获得新观测后重规划，仍走原逼近与清除闭环。
- 该预计目标只是启发式，未计算完整贝叶斯后验或未来所有测量结果。实验未发现它能稳定节省时间，不能把失败归结为联合规划思路在所有实现上都无效。

## 使用与复现

默认配置的两个开关均为false；单独试动态覆盖用 `configs/experiment_adaptive.json`，联合行程用 `configs/experiment_joint.json`，组合用 `configs/experiment_combined.json`。

```powershell
python scripts/run_offline.py --config configs/experiment_adaptive.json --cases 100 --start-seed 24000 --outdir outputs/adaptive_followup
python scripts/compare_search_experiments.py --outdir logs/experiments/search_repeat --start-seed 22000 --cases 200
```

独立实验脚本拒绝覆盖已有目录；仅在参数、代码哈希一致时允许用相同命令加 `--resume` 续跑。
