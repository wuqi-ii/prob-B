# 多起点路线优化实验（2026-09-12）

本轮最佳候选：configs/multistart_shared_01.json。默认仍保留原策略，全部测试为离线，未连接2026端口。

## 方法

保留七点全覆盖、1150米环半径、最坏接收1000米、标准第二点(764,±526)、近端试测比例0.1、共享观测和清除后复测。改变任务访问顺序：

1. 保留原插入路线，对其做开放路线2-opt作为候选。
2. 分别假设每个当前任务是下一步，最近邻补全其余任务，再对后续路线做2-opt。
3. 比较候选的总移动距离，执行最短候选的第一项；取得真实观测后全部重算。

2-opt最多20轮，任务量受20频道和7扫描点约束。未预测尚未发现目标；验证后的未知清除位置也未完整纳入路线。因此这是有限候选路线搜索，不是完整随机动态规划或全局最优证明。配置route_multistart内部自带2-opt，不需要再开route_polish。

还实现了adaptive_verify：从五个近端比例与左右侧取候选，以可行域内部位置和±1°误差情景估计后续路程、残余误差，保留标准点兜底。评分只是启发式，未取得更好结果，推荐配置关闭。预测仅作评分，不写入真实观测。

探索28000–28029：6组×30局，每组376/376全清。均时：原基线3482.94秒，上一候选3329.88秒，比例0.05为3334.52秒，自适应补测3395.96秒，多起点路线3207.06秒，自适应补测+多起点3371.42秒。由此预选多起点路线，不把探索7.92%当最终收益。
