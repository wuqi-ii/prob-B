# 日志发现的三项问题：修复与独立验证

本轮只做离线实验，未连接2026端口。推荐候选为 `configs/optimized_threefix.json`，原默认配置仍未改变。

## 三项修改

1. **真实角度输出的稳健性**：四次真实演练共205条方向反馈全部在0.01°刻度。若物理误差±1°后再四舍五入，显示值相对真值最多可到±1.005°。定位楔形增加0.005001°舍入容差；物理误差假设没有放宽，只覆盖显示量化。极限固定误差±1.005°、10目标定向场景由原8/10提升到10/10全清。
2. **16源完成即停止**：仅当实际成功清除16个不同频道时，依据题设总数上限停止剩余扫描；发现16个但未清除完不会停止。固定16源的50局中，均时3464.84→3419.50秒，省45.34秒；10局更快、其余40局相同，800/800全清。混合10–16源时总体仅省0.46秒，符合该规则只作用于16源长尾。
3. **扫描融入完整服务路线**：七个固定点仍是兜底。仅当“已完成无信号圆＋候选扫描点＋其他剩余扫描点”通过连续1000米圆覆盖证明，才允许把下一扫描点向当前位置或清除/定位任务方向平移。候选点不只按局部两段路程，而是放入全部扫描、验证和清除任务路线，最近邻补全并开放2-opt后比较整条路线。执行前再次验证覆盖；失败则回原固定点。每次真实反馈后重算。

## 独立结果

探索使用seed38000–38029；参数选择后使用未参与选择的seed40000–40199进行200局独立验证。

| 方案 | 平均虚拟时间 | 相对原基线 | 全清 |
|---|---:|---:|---:|
| 原基线 | 3473.24秒 | — | 2615/2615 |
| 稳健多起点候选（不提前停、不平移） | 3237.77秒 | -6.78% | 2615/2615 |
| 加16源停止 | 3237.31秒 | -6.79% | 2615/2615 |
| 加完整路线扫描平移 | **3223.45秒** | **-7.19%** | **2615/2615** |

最终候选比原基线平均省249.80秒，200局中185局更快、15局更慢。与稳健候选相比，扫描平移及提前停止合计再省14.33秒，配对近似95%区间[8.59,20.07]秒；主要来自移动距离。不要把不同百分比直接相加。

全体接收半径固定1000米的独立50局（seed41000–41049）：稳健候选3274.79秒，最终候选3259.54秒，再省15.24秒，区间[3.86,26.63]秒；各667/667全清。

这些结果证明在当前离线分布中有小而稳定的增益，不证明对任意源分布达到全局最优。扫描平移保留连续覆盖证书，但证书算法数值上保守：无法证明时会拒绝平移而回退固定七点。
